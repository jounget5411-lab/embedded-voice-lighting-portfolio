# 실행 준비와 현재 확인 상태

## 준비물

- Arduino UNO/ATmega328P 2개와 보드별 USB 연결
- MAX4466 마이크, HC-SR04, 공통 애노드 RGB LED 및 저항
- A/B 공통 GND, SPI와 UART 배선
- Arduino 환경에서 AVR 보드 패키지와 선택 sketch의 include 확인
- PC Python 환경: 공개한 도구의 import에 맞춰 NumPy, pandas, scikit-learn, pyserial 등 설치

정확한 보드·도구 버전의 새 빌드 검증은 하지 않았습니다. 배선과 레지스터 설정은 sketch를 기준으로 확인하며, MCU 직접 레지스터를 사용하는 부분을 다른 보드에 그대로 적용하지 않습니다.

## 파일 준비

1. `firmware/A_wclh_5`와 `firmware/B_wclh_5`를 각 sketch 폴더로 사용합니다.
2. B sketch와 `weights_wclh_k5.h`를 같은 폴더에 둡니다.
3. `log_features_serial_5bin.py`의 COM 포트·baud rate·`--bins`를 실제 바이너리 전송 경로와 순서에 맞춥니다. 기본 bins는 1100,1200,2200,2300,800이고 선택 A의 배열은 1100,1200,2200,800,2300입니다. 선택 A sketch의 USB Serial은 디버그 텍스트 출력이므로 현재 sketch를 업로드하고 USB에 수집 도구를 연결하는 것만으로 동작한다고 보장하지 않습니다.
4. 수집 결과에 실제 명령 라벨을 연결하고 학습 CSV의 열 순서와 A보드 Goertzel 순서를 맞춘 뒤 모델 헤더를 생성합니다. 수집 도구가 저장하는 CSV에는 자동 정답 라벨이 없습니다.
5. 같은 입력에서 PC 계산과 MCU 클래스 점수를 대조한 뒤 보드 통합을 확인합니다.

이번 공개 정리에서는 이 절차를 실행하지 않았습니다. 동작 가능한 최종 조합을 확인하려면 헤더의 출처와 PC/MCU 특징 순서부터 대조해야 합니다.

## 통합 확인 순서

| 단계 | 관찰할 내용 |
|---|---|
| A만 연결 | 샘플링·프레임 생성, 특징 값의 범위, 프레임 간격 |
| B와 SPI 연결 | 패킷 길이·체크섬·프레임 누적, class score |
| UART 경로 | SPI 의도 단선 후 폴백, SPI 복구 시 복귀 |
| 실제 출력 | 근접 조건, Warm/Cool·Low/High 명령, 불응기 |

이 표는 다음 하드웨어 재현의 체크 항목입니다. 공개 시연 영상과 보고서는 당시 구현의 근거로 제공하며, 현재 환경에서 재실행한 시험 결과와 섞지 않습니다.

## 이번 정리에서 완료한 확인

선별 소스의 기능·버전 대조, 보고서와 수치의 범위 구분, 문서·코드 경로 확인. 보드 빌드/업로드, 전체 데이터 재학습, 현장 정확도·장시간 운용 시험은 수행하지 않았습니다.

# 개발 과정과 설계 판단

## 20 ms 계산 중에도 다음 샘플을 받기

ATmega328P의 작은 SRAM과 연산 자원에서 샘플 취득·특징 계산·통신을 함께 수행해야 했습니다. 8 kHz 취득은 인터럽트에서 유지하고, 프레임이 완성되면 버퍼를 교대해 메인 루프에서 계산하도록 분리했습니다. 정수 필터·정수 제곱근·Goertzel을 사용해 연산을 구성했습니다.

## 통신 변경이 추론 입력을 바꾸지 않도록

보존 폴더에는 UART 중심 시험, SPI 시험, SPI/UART 결합, RGB LED, 초음파 통합 순서의 구현이 남아 있습니다. 공개본은 거리 조건까지 포함한 시도7의 A/B를 선택했습니다. 서로 다른 링크에서 동일한 패킷을 사용하고, 실패 횟수와 복귀 조건을 전송 상태로 관리하도록 했습니다.

이는 소스에 남은 구현과 보고서의 단선 시험을 설명한 것입니다. 모든 과거 오류의 발생 로그나 각 변경 전후의 개선율을 새로 재현한 기록은 아닙니다.

## 음성 분류를 실제 명령으로 바꾸기

프레임별 분류는 흔들릴 수 있고 같은 발화가 여러 프레임에 걸칠 수 있습니다. 무음 gate와 투표·연속 확인·불응기로 명령 반영 조건을 만들고, 초음파 근접 조건을 마지막 출력 gate로 결합했습니다. 거리 측정이 포함된 B sketch 중 `pulseIn` 버전과 Timer1 입력 캡처 버전을 구분해 후자를 선택했습니다.

## PC와 MCU의 입력 순서 대조

A보드의 Goertzel 순서는 `{1100,1200,2200,800,2300}`입니다. 일부 PC 학습 코드·모델 메타데이터는 마지막 두 특징이 `{2300,800}` 순서입니다. B는 수신 특징을 그대로 누적하므로 사용한 CSV의 열 순서, 학습 입력 순서, 모델 헤더의 각 열 의미를 함께 확인해야 합니다.

파일명이나 최신 수정 시각만으로 이 연결을 확정하지 않았습니다. 공개한 코드는 보존된 구현을 읽기 위한 기준이며, 특징 순서 차이만으로 당시 사용 모델 전체가 잘못 동작했다고 단정하지도 않습니다.

## 다음 재현에서 확인할 항목

| 확인 | 의미 |
|---|---|
| 동일 프레임의 PC/MCU 클래스 점수 | 정수화와 특징 순서의 대응 확인 |
| 의도적 SPI/UART 단선·복구 | 링크 상태 전환과 출력 유지 확인 |
| 프레임 처리/추론/명령 반영 구간 분리 | CPU 처리 시간과 사용자 체감 지연 구분 |
| Timer1 입력 캡처·RGB PWM 핀 대조 | 코드의 타이머 구성과 실배선 확인 |

위 표는 재현 계획이며 이번 정리에서 새로 완료한 시험 목록이 아닙니다.
